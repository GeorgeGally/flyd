Ideation

Make Flyd a personal work assistant

22 August 2026 · Topic: personal-assistant · Grounded in the active Flyd work-intelligence product and runtime

Grounding context

Flyd’s active authority already defines a personal work loop: Ground → Diagnose → Intervene → Act → Verify → Learn. Current implementation has safety, repository actions, session storage, a Present Model, closeouts, learning candidates, and scheduled briefs. But the foreground model still infers too much from the focused element and branch; key fields such as constraints and open loops are thin; and an interaction often terminates as a cursor-side response. The opportunity is to productize continuity and verified progress, not add a more capable chat shell or speculative background autonomy.

Topic axes

Live work understanding · Continuity and memory · Intervention-to-outcome loop · Cross-app action capability · Trust-calibrated initiative

Ranked ideas

  1. Visible working contract

    Description: Start each substantial interaction with a small editable model of the work: objective, artifact, stage, constraints, open loops, next move, evidence and confidence. Let a correction update the contract, not merely the chat history.

    Axis: Live work understanding
    Basis: direct: the PRD requires these Current Work fields, while current-work.ts currently leaves constraints/open loops thin.
    Rationale: A shared, inspectable situation model gives Flyd a reason to act beyond answering the latest prompt.
    Downside: Must remain compact or it becomes a dashboard.
    Confidence 95%Complexity Medium

  2. Project reconstruction, not chat resumption

    Description: Offer a deliberate “reconstruct this project” action that reads the diff, recent commits, plans and current docs, then returns what changed, what is blocked, what is stale and one recommended next move.

    Axis: Continuity and memory
    Basis: direct: the PRD prioritises foreground/repository/current-document evidence; the current objective can collapse to “work on branch.”
    Rationale: Eliminating re-explanation is a distinctly assistant-like advantage over a chat thread.
    Downside: Needs evidence freshness and a clear scope boundary.
    Confidence 94%Complexity Medium

  3. Turn the augment card into a verified action loop

    Description: Make the default interaction flow: diagnosis → preview/draft → approval → apply → re-read or test → outcome receipt. A response card should be one state in the loop, not the terminus.

    Axis: Intervention-to-outcome loop
    Basis: direct: Flyd already has proposal binding and repository verification plumbing; the PRD makes verification a product obligation.
    Rationale: Users experience progress and trustworthy receipts, not fluent commentary.
    Downside: Requires disciplined state/UI design across surfaces.
    Confidence 93%Complexity High

  4. “Stop here” as a first-class closeout

    Description: At the end of real work, capture verified changes, decisions and rationale, unresolved risks, next committed move, and only durable learnings. Rehydrate that record on return.

    Axis: Continuity and memory
    Basis: direct: closeout and learning scaffolding exists, and the PRD specifies this exact continuation contract.
    Rationale: It gives Flyd a memory of work outcomes rather than a transcript of conversation.
    Downside: Needs a near-zero-friction capture interaction.
    Confidence 92%Complexity Medium

  5. Confidence-gated resume brief

    Description: When Flyd recognises a project/artifact with strong evidence, surface a one-screen brief: last verified state, open loop, stale assumption and “start here.” Otherwise stay quiet.

    Axis: Trust-calibrated initiative
    Basis: external: selective daily cards and moment-aware assistance outperform a feed; Flyd’s PRD prohibits speculative interruption.
    Rationale: It feels present without becoming noisy or autonomous theatre.
    Downside: Requires careful confidence thresholds and suppression controls.
    Confidence 90%Complexity Medium

  6. Decision critic and smallest decisive test

    Description: For an active decision, identify the weakest untested dependency, conflicting prior rationale and evidence gap; recommend the smallest reversible test that would change the decision.

    Axis: Intervention-to-outcome loop
    Basis: direct: the strategy/PRD call for causal diagnosis, disagreement and decision-quality—not generic praise.
    Rationale: This gives Flyd judgment that materially changes work, rather than another answer generator.
    Downside: Needs strong domain standards to avoid performative critique.
    Confidence 88%Complexity Medium

  7. Grounded visual critique

    Description: Let Flyd point to named screen regions or selected text, attach evidence to the claim, and offer an annotation or proposed local edit.

    Axis: Live work understanding
    Basis: direct: selected-region and augment capabilities exist; the active product calls for on-screen pointing and annotation.
    Rationale: The assistant works on the artifact in front of the user, rather than speaking beside it.
    Downside: Visual grounding must fail honestly when capture is insufficient.
    Confidence 86%Complexity High

  8. Inspectable “how Flyd works with me” profile

    Description: Expose learned standards, active projects, trusted sources, correction history and negative preferences as an editable contract with provenance and expiry.

    Axis: Continuity and memory
    Basis: external: permissioned agents make durable instructions visible; Flyd already requires provenance, correction and deletion for material memories.
    Rationale: Personalisation becomes legible and controllable, so it earns trust.
    Downside: Must not become a generic settings/database UI.
    Confidence 84%Complexity Medium

  9. Outcome learning from acceptance and rejection

    Description: After an intervention, ask at most one contextual feedback question; connect acceptance, rejection, undo and later verification to the work contract and use only repeatable patterns later.

    Axis: Trust-calibrated initiative
    Basis: direct: the PRD says learn from accepted/rejected interventions and measure effect; the outcome journal exists but is not yet a rich causal loop.
    Rationale: Flyd gets better at when and how to help this user, not merely what to remember.
    Downside: Feedback must be optional and sparse.
    Confidence 84%Complexity Medium

  10. One-screen advance brief

    Description: For a real decision, review or research gap, create a short packet: current state, evidence, one recommendation, trade-offs and the next executable move—with an option to do it.

    Axis: Cross-app action capability
    Basis: direct: Flyd’s intervention contract calls for one high-leverage recommendation and an offered next action; daily briefs and jobs already provide a bounded briefing substrate.
    Rationale: It turns ambient context into a moment-specific move forward, rather than a chat answer or a telemetry dump.
    Downside: Must be reserved for moments with sufficient evidence and a real decision.
    Confidence 82%Complexity Medium

Rejection summary

Broad integration catalogue — too diffuse before one reliable work loop. Always-on proactive assistant — conflicts with Flyd’s PRESENT privacy/scope constraints. Generic dashboard — creates a second primary interface rather than improving the present moment. More chatbot/persona modes — treats the symptom rather than continuity, action and verification.
